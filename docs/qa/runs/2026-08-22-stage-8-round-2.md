## What this run found

Three of the six new procedures failed on their first run, and all three were wrong
*procedures*, not defects:

- **2.6 and 2.9** reloaded the page and then looked for the company list. A reload returns you
  to the board, so the list was not on screen. The written procedure said "Reload: still the
  new name", which a person would also have found misleading. Both the document and the script
  now say to reopen **Companies** after reloading.
- **2.8** refused a blank rename, then looked for the old name as text. The row is still an open
  edit form at that point, so the name is in an input rather than in the list's text. The
  procedure now says to press **Cancel** first, which is what a person would do anyway.

## Proof these procedures can fail

The project's standard is that a check nobody has seen fail is not a check. `companies.save`
was removed from `RenameCompanyInteractor` and the suite re-run:

```
✘ QA-2.6 a company can be renamed and the new name survives a reload
✘ QA-2.7 a deal follows its company across a rename
2 failed, 9 passed
```

Two independent procedures caught it, and the other nine correctly stayed green. The line was
restored and the suite is green again.
